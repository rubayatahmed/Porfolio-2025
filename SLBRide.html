Design Brief

Dgitising the process of fleet and booking management for the travel coordinators of SLB along with maximising vehicle utilisation.

Solution Statement

Eric use SLB Ride to assign vehicles to rides while ensuring efficiency in capacity utilisation. In the past, he used a white board and manually called drivers to pick up rides but switches to SLB ride when it became a mess to handle many requests manually.

Detailed Request View

User go through the details of the request and made necessary changes in timing and approve/reject ride. The Ride Details screen is divided into 4 parts -

1. Request Metadata : The title bar containing the metadata

2. Request Details : The right hand side panel having all the details entered by user through the booking application to consider while planing. This section again categorised into 3 options - Address & Time, Other Details, passenger Details

3. Actions : The action bar at the bottom displays current status of ride and actionable buttons

4. Live Tracking Board : This is the central area that is disabled until user approves the ride. A gantt chart view of live trips are displayed here to assist the user in assignment in the next stage.

Ride Assignment and Trip Creation Process


This part bringing the core value of the application, it allows users to efficiently assign rides to vehicles and create new trips based on availability and location.


Based on the details travel coordinator approves/rejects the requests. Once approved the live tracking board get's enabled so that vehicles can be assigned.

Once approved it’s time for assigning the request to a vehicle and driver. As shown in the user flow we prioritise on showing the suitable upcoming trips around the locations, if nothing came out from that the user has option to assign it to a new vehicle/driver, where results in a new trip.

Allotment to an existing Upcoming trip isn't that straitforward!

To allot a request into an upcoming trip, the following factors are crucial to know for the user, which has been incorporated in the adaptive cards in the timeline UI.

1. Available occupancy in the Vehicle

2. Pickup and drop of the trip to help the user to plan accordingly to optimise the time between stops

3. Time of the ride

Check compatibility between the rides

Clicking on a suitable trip card opens up route details so that user can make a informed decision. The UI dynamically shows compatibility with the new ride added, which user can confirm if needed.

Or Assign a New Trip

On contrary, vehicles who are sitting idle are listed next in the tracking board, user shall click on assign button to assign that vehicle. This button is diabled for the vehicles who has trips overlapped at that time slot.

Visual Cues of the Tracking Board

Selected Trip

In a view dominated by similar trip cards it is very important to highlight the selected trip for better visibility and interaction.

Colour Coding

Colour coding is used to indicate the status of the trip, such as orange for ongoing, violet for upcoming, and grey for completed.

Tooltips

Hovering over a trip card provides additional information through tooltips. Also for longer address line tooltip helps to read the full address.

Next Day Indicator

The next day is in the timeline is indicated by a pattern visual marker, which helps users quickly identify the difference.

Reflection

Complex problems are like icebergs — most see only the tip. It’s on you to dive deeper, uncover what’s hidden, and design in a way that abstracts that complexity for everyone else.

Designing the SLB Ride application was a complex yet rewarding experience. The more we delved into the system complexities of inventory management and live monitoring, the more we realized the importance of a well-thought-out design that not only work & sustain but also provide value to business.

Another key learning was the importance of user feedback and iterative design. By continuously engaging with users and incorporating their insights, along with discussing solutions with developer and PO, we were able to build something that truly met the needs of our users.

But most importantly, I have had a great time solving such complex problems with design, and how iterative abstractions can simplify complex interactions.
