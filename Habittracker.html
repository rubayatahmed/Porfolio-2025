Habit Tracker and Visualiser


An exploration into designing a habit tracking and visualisation system and building it using claude.

Project details

  • Category:Prroductivity Project
  • Year: 2026
  • Expertise:Interaction Design, Prototyping, Data Visualization, Vibe Coding
  • Area:Productivity, Health & Wellness

Context

If you’ve ever tracked your habits consistently, you probably know that strangely satisfying feeling of looking back at a calendar full of completed days

I have been tracking my habits with notion calendar templates, it has been great to be honest, I like seeing it on calendar. I noticed that most habit trackers focus heavily on streaks and gamification, while my own workflow relied more on visual consistency and reflection through calendar logging in Notion.

But over time, I started to feel the friction of notion interactions, I know it’s a great tool and admire the design, but to do a specific task regularly it felt somewhat overwhelming. Also the visualisation aspects was pretty limited having less scope for customisation. Which led to me to this project.

Personal Choices

I recognize that there is significant potential to explore habit formation through behavioral psychology, gamification, rewards, accountability systems, and other behavior-driven approaches. However, I intentionally chose to constrain the scope of this project to a specific design direction.

My goal was to build a habit tracker around the calendar as the primary organizing principle.

Similar to how Uber is built around a map, Airbnb is built around location-based discovery, Figma is built around an infinite canvas, Trello is built around boards and cards, Notion is built around blocks, and Spotify is built around collections of playlists and libraries, this product is centered on the calendar. The calendar is not just a feature—it is the foundation upon which the entire experience is built.

A few Assumptions

To keep the project focused, I made several assumptions based on some existing research and my own experience with habit tracking.

1. Users derive value from seeing their progress over time, and visual self-monitoring can support continued awareness and engagement.

2. Calendar-based interfaces are familiar to most users and are effective for identifying temporal patterns, trends, and gaps in behavior over time.

3. Reflection and awareness are more valuable for this concept than gamification, streaks, rewards, or competitive mechanics.

4. Users primarily want to answer a simple question: "How consistently have I shown up over time?"

5. Users are already motivated to track habits and do not require extensive behavioral interventions to get started.

6. To limit the project's scope, I assumed users would be comfortable using a desktop-first experience. While habit tracking is commonly associated with mobile devices, the objective of this project was to explore the calendar interaction model rather than optimize for mobile usage.

Quantifying hobbies

The Input


To make behavior visible, it first had to become measurable.


So we needed a way to quantify everyday behavior. I was already doing it in notion using various input fields, but the problem with notion was that the fields were too vanila so I put together five primary inputs that can accommodate almost all types of hobbies.

Checkboxes, Numerical Inputs, Slider(Percentage), Rating and Dropdown Values

Additional Notes

I also added a seperate note section apart from the hobbies, which can be used to add any additional information about the hobby or the day.

Idea is to fetch this texts fo AI summarization and provide a summary of the week or a specific period.

The Calendar

The calendar is the core of the habit tracking experience, providing a visual representation of the user's progress over time. Each day is represented by a card that displays the logging status and allows for quick interactions.

Carefully designed day cards on the calender view not only acts as interaction touchpoint but shows the logging status.

Monthly, Quarterly & Yearly Views

The calender view is designed to provide users with multiple perspectives on their habit tracking data. The monthly view offers a detailed look at daily logging, while the quarterly and yearly views provide a broader overview of trends and patterns over time. This multi-level approach might not be usefull while logging information but it came from the visualisation purpose.

Here are the Quarterly and Yearly Views:

The default calender on it's own visualises the logging status, but It can do much more than this if we combine the habit data and show it meaningfully. For example how many days I had sketched last month, what was my average working hours in the last quarter, how many days I had a good sleep in the last year. This is where the visualisation comes into play.

This feature has been highly insprired by Github's contribution chart, which shows the contribution of a user over the year in a calender heatmap. I wanted to do something similar but with more flexibility and customisation.

Now, let's see how the visualisation works and look like in the next section.

The Visualisation

The value of visualization lies not in showing data, but in helping people discover what they couldn't easily see before

The Overview Panel

The Overview panel provides a comprehensive view of the user's habit tracking data, It summarizes key metrices like days logged, streaks, and completion rates, average values, max-min values for all the hobbies that the user has tracked. Based on the type of the hobby the key matrices also vary. For example a graph for discrete values or a percentage bar for binary values.

The overview panel represent the calender period so if you change it to a different time frame, you will see the corresponding data. Along with it the top header displays a quick summary of the user's progress.

Translating numbers into the calendar

the 5 types of inputs that I have mentioned earlier can be visualised in the calender in 3 ways, One is by showing two colors for binary values, second is by showing a seperate color for each discrete value for the dropdown values and lastly a increasing color intensity for the percentage values, numbers and ratings. This way the user can easily see the progress of a specific hobby in the calender view.

Trends, Insights and Meanings

Another layer of direct insights has also been provided for each hobbies which take up the top header space and provide intelligent analysis of the hobby's progress over the selected time frame. This is a simple way to provide insights to users who loves to see the numbers and trends but don't want to go through the hassle of analysing the data themselves.

Reflection

Interactive data visualisation with meaningful insights can create magic.

This project pushed me to think critically about how data can be presented in a way that is not only informative but also engaging and actionable.

I see a great potential of this approach of data centric habit tracking. Hence continueing this work and developing it further using spec-driven development framework. Once the coded prototype is ready I'll move to the next phase of designing which will be focused on making it mobile first and accessible thorugh various input integrations such as whatsapp, smartwatch and more. Also the gamification elements can be of great help to consider.
